# 資料與公開範圍規則

## 可以公開與必須受限的內容

通用協作規則、空白範本與經確認可公開的程式可以在使用者明確授權後提交。公開前要檢查檔案及這次將推送的整段提交歷史，不只檢查最後一版。

以下內容保存在核准的受限位置，不放公開 repository、PR、Issue、日誌或測試輸出：

- 真實專案、人員與客戶名單、業務資料及財務值。
- 個人登入碼、token、服務憑證及完整資料備份。
- 詳細部署識別資訊、內部維運紀錄、未公開的問題證據與包含上述內容的截圖。

測試只使用完整虛構資料；遮住部分欄位或改名字的正式資料仍不作測試樣本。正式資料副本是備份，不是測試 fixture。

## 保護範圍要分開確認

| 範圍 | 必須查明的事 |
| --- | --- |
| 原始碼倉庫 | 誰能讀目前檔案、歷史、分支及相關副本 |
| 網站入口 | 未授權者是否能從主網域、預設網域、預覽或資源直連取得內容 |
| 後端資料 | 每次取得名單、讀取或修改資料時，是否由後端驗證身分與權限 |

私有倉庫不等於私有網站，畫面隱藏不等於後端沒有回傳資料。瀏覽器執行所需的 HTML／JavaScript 會送給使用者，不能承諾合法使用者無法檢視前端程式。

## 發現不該公開的內容

先記錄受影響範圍並停止擴散，保留必要證據於受限位置。刪掉最新版不會自動清除 Git 歷史或外部副本；不得自行 force-push、刪除倉庫或改寫別人的工作。

由具權限管理者依具體影響安排限制存取、憑證處理或歷史清理。涉及服務中斷、破壞性操作或擴大存取時，須遵循使用者授權與[發布手冊](RELEASE_RUNBOOK.md)。

`.gitignore` 只能減少誤加入檔案，不能清除已追蹤內容，也不是秘密偵測器。實際資料與證據放在受限位置；即使倉庫私有，也不把它當正式資料備份系統。
