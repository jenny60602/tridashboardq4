# 分頁草稿與同步可靠性

本批接在事件監聽器 PR 後面，只改前端同步與復原流程；不部署 GAS、不修改正式試算表，也不提供後端欄位白名單或持久備份。

## 使用上的變化

- 未同步草稿保留在同一分頁的 `sessionStorage`，包含登入身分、同步基準及目前修改。重新整理後必須通過伺服器驗證，才能提供同身分的復原選項。關閉分頁或確認登出仍會失去分頁草稿。
- 雲端已有資料時也會提示草稿。處理前暫停編輯、自動同步及已排隊的寫入，避免新操作覆蓋待處理草稿。可選擇復原並在衝突處保留雲端、採用草稿，或確認放棄草稿。
- 復原會再讀取最新雲端資料，沿用既有三方合併規則。不同欄位合併；一般同欄位衝突依所選方向處理。既有以 ID 合併清單、文字清單增刪規則維持原狀。
- 財務復原依最新伺服器資料中的負責人與目前角色判定，不能用草稿中的舊負責人恢復已失去的權限。唯讀 `_fin` 一律使用最新伺服器值。尚未送出的新專案若未取得財務權限，只復原非財務內容。
- 沒有同步基準的舊版備份不會直接覆蓋雲端；與雲端不同時會保留並提示。需保留分頁由管理者協助核對，或由使用者明確放棄。與雲端相同的暫存可以清除。
- 分頁儲存失敗會另顯示持續警告，不能再聲稱最新修改已成功暫存。雲端確認同步後會清除草稿，若清除失敗也會明確警告。

## 連線與不確定的寫入

每次請求最多等待 30 秒，包含回應內容讀取及 JSON 解析。逾時會中止瀏覽器等待、釋放同步佇列；登出亦會取消目前等待，舊回應不能重新填入畫面。舊後端的 capability ping 防護保留，每次 POST 之前仍確認 API 版本。

送出寫入前就會保存同步基準、送出版本與最新草稿。如果送出後逾時或連線中斷，**無法據此判定伺服器沒有寫入**。程式會保留草稿，暫停自動重送及後續排隊寫入。使用者明確選擇復原後才重新驗證、讀取雲端及合併；復原前會提示不確定結果。復原先處理送出版本，再合併等待期間的新修改，包含將欄位改回原值的情況。

取消瀏覽器請求及放棄草稿都不能撤回已送到 GAS 的寫入。本批沒有新增伺服器操作 ID、去重或交易完成查詢，因此不保證 exactly-once，也無法排除很晚才完成的原寫入；這需要獨立後端設計與驗證。

## 驗證邊界

所有測試使用虛構專案、假身分、假密碼及明確排入的離線回應。禁止連正式 dashboard、GAS 或試算表；禁止讀取歷史真實 catalog 或匯入正式備份。離線測試不能代替正式 GAS 的整合及部署驗收。

```sh
node --test tests/auth-backend.test.cjs tests/auth-frontend.test.cjs tests/catalog.test.cjs tests/events.test.cjs tests/helpers/synthetic-environment.test.cjs tests/sync-recovery.test.cjs
```

此 PR 依賴登入及事件監聽器兩個前置 PR。尚未合併或部署時，正式環境行為不會改變。
