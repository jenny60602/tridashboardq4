# 登入後才能查看與修改儀表板：部署協調說明

這個 PR 只準備程式變更與離線測試，不自動合併或部署。正式 GAS 部署與前端上線需要一起協調，PR 應保持 draft，直到部署擁有權者確認安排。

## 先核對正式基準並備份

由有部署權限的擁有權者核對：目前網頁使用哪個 GAS Web App、實際部署版本及其原始碼、綁定哪份試算表，以及現有權限設定。編輯器最新內容不一定就是已部署版本。

變更前保存目前部署程式與試算表資料的可用備份，並確認如何復原。歷史紀錄曾發生舊後端將讀取 POST 誤當 state 寫入；不能把前端改版、合併保護或專案軟刪除當成完整復原機制。本 PR 不執行備份、正式驗證或復原操作。

## 私有 catalog 的準備

在具有原始 commit 的本機 checkout 執行：

```sh
node scripts/prepare-catalog.cjs
```

工具只從本機 Git commit `876e933dcd0e25a7ba9010e2332a79109c9fdf02` 的 `index.html` 擷取 `const PROJECTS` 起、`const STATUSES` 前的已知資料宣告。它不執行完整 HTML；先限制宣告與資料語法，再於禁止字串／Wasm 程式生成、100 毫秒時限且沒有主機 API 的 VM 中取得 catalog。工具不連 GAS、Google Sheets 或其他網路。

輸出是 `.private/Catalog.gs`，僅包含 `DASHBOARD_CATALOG` 常數：專案 `id/cat/name/months`、兩組員工、合作夥伴及角色。標準輸出只顯示數量與檔案路徑。`.private/` 已在 `.gitignore`，不得強制加入 Git，也不要將真實名單複製進測試、PR 描述或附件。

若輸出已存在，工具會拒絕覆寫；沒有 `--force` 或刪除功能。請擁有者先人工檢查及保留舊檔，再自行決定是否需要重新產生。這份 catalog 來自固定歷史基準，擁有者需在私人環境核對是否符合目前名單。

## GAS 的人工整合範圍

將 `gas/Authentication.gs` 的入口函式內容整合到私人 GAS，**替換現有 `doGet`／`doPost`，不能同時保留兩套同名入口**。不要整份覆蓋現有 GAS 專案。保留既有 `json_`、`lookupUser_`、`redact_`、`mergeWrite_`、`mergeState` 等函式，以及私有 `setup`、`FIN_SEED` 和其他既有程式；依新增入口所需補入相應驗證輔助函式。

在私人 GAS 新增未提交的 `Catalog.gs`，貼入本機產生並人工核對的內容。**不要執行 `setup`**。正式 state、權限分頁、財務資料和既有財務保護均不搬移、不改寫；本次只把原本內嵌在公開前端的 catalog 改由登入後取得。前後端合併程式原本需要保持一致，這次整合不能順帶換掉其中一份。

## 部署順序與使用者影響

1. 擁有者安排相容部署窗口，確認備份及復原安排，再整合私人 catalog 與入口。
2. **先部署回報 `api:4`、`authRequired:true` 的 GAS 後端**，並由擁有者按另行確認的驗收安排檢查。
3. 後端準備完成後，才解除 draft、完成前端 PR 的合併與發布協調。這份 PR 不會自動做這些動作。

若反過來先上新版前端，遇到舊後端會 fail closed，使用者將無法使用，直到後端完成升級。新版後端上線後，舊有已開啟頁面的匿名請求會被拒絕；已有有效登入資訊的相容請求可繼續使用。所有人仍應在前端發布完成後重新整理，以取得新的登入與 catalog 流程。部署擁有者需要把這段使用影響事先納入窗口安排。

## 邊界與驗證狀態

登入仍使用既有個人密碼與權限分頁；一般使用者（`none`）可登入，登入後的財務、指派及付款限制沿用原規則。這次不新增「只能修改自己負責的專案」限制。

密碼仍放在該分頁的 `sessionStorage`。重新整理會先重新向伺服器驗證，成功後才顯示資料；首次開啟或重新整理時無法連線，就不會用本機備份解鎖。一般關閉分頁後需重新登入；瀏覽器的工作階段還原功能可能保留 `sessionStorage`，不能視為嚴格的關閉即撤銷機制。

登出會立即清除畫面、記憶體資料及該分頁的備份，並取消尚未送出的排隊寫入；有未同步修改時會先提示確認。已送達伺服器的寫入無法靠登出撤回。密碼失效或身分改變時直接鎖定並清除，不等待存檔。新備份附帶登入身分，只會在同一身分通過驗證後提供復原；舊的無身分備份不會自動匯入。上線前應請使用者先完成同步，再重新整理。

這項變更限制後續從新版應用程式匿名取得內容，**無法撤回已暴露於公開 Git 歷史的資料**，也不會抹除既有瀏覽器或他人保存的副本。本 PR 不變更 repository visibility，也不改寫 Git history。

本輪僅執行合成資料的離線測試；沒有執行正式部署、live smoke、真實登入、資料寫入或復原測試。部署驗收及真正的可復原性仍須由擁有者在協調後確認。

