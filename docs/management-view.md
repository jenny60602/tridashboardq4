# 經營檢視（主管限定）設計說明

狀態：**開發預覽，未合併、未部署**。分支 `feature/management-dashboard-preview`，追蹤 Issue #22。

本文件只描述程式與資料結構。白名單名稱、財務摘要試算表 ID、任何財務數字都不放在這個公開儲存庫。

## 1. 權限設計

沿用現有登入：個人密碼（「權限」分頁）換 6 小時通行證。不另建登入系統。

```
瀏覽器 ──execRead + 通行證──▶ GAS doPost
                               ├ sessionUser_(token)：用通行證查出伺服器端的姓名（每次重查「權限」分頁）
                               ├ execCanView_：姓名 ∈ 指令碼屬性 EXEC_VIEWERS？  否 → {ok:false,error:'forbidden'}
                               ├ EXEC_SHEET_ID 必須是「另一份」試算表（與儀表板相同就拒絕）
                               └ 讀「財務摘要」「週會決策紀錄」→ 逐列驗證 → 只回給這個人；寫一筆存取紀錄
```

| 層級 | 做法 |
| --- | --- |
| 前端頁籤／導覽 | 「經營檢視」頁籤預設隱藏，只有伺服器回 `ok` 才顯示；強制打開或直接呼叫 API 仍被伺服器拒絕（已測） |
| 後端存取 | 只看伺服器端身分與 `EXEC_VIEWERS`；與「管理者／財務／本人負責」等級**無關**，等級再高、不在名單也拒絕。沒設定名單 = 沒有人能看（fail closed） |
| 資料來源 | 財務摘要與週會決策紀錄放在**獨立試算表**，不放在所有人共用的 `State`；現有 `read`／`write` 回應、分頁草稿、Excel 匯出都不含這些資料（已測） |
| 匯出 | 第一階段不提供經營檢視的匯出；現有 Excel 匯出只讀專案資料 |
| 清除 | 登出、通行證失效、換人登入時，記憶體與畫面立即清除；不存 localStorage／sessionStorage |

### 帳號識別（待確認，未設定）

`EXEC_VIEWERS` 要填「權限」分頁 A 欄的**確切名稱**。這份清單由擁有者在 GAS 指令碼屬性設定，程式裡沒有寫死任何人。

需要確認的事：「權限」分頁裡兩位指定主管（負責人、營運主管）各自對應哪一列的名稱（同一人可能有中文名或英文名兩種寫法）。未確認前不設定，系統維持「沒有人能看」。

### 殘餘風險與隔離方案

這個做法把財務摘要和專案資料分開，但仍共用同一個 Apps Script 專案：

- **能編輯這個 Apps Script 專案的人**（擁有者及協作編輯者）技術上可以修改程式或讀取指令碼屬性，進而讀到財務摘要。
- **財務摘要試算表的分享對象**可以直接打開試算表。

因此正式啟用前請確認：

1. 財務摘要試算表只分享給擁有者（以及確認人），不分享給一般同事。
2. 若 GAS 專案有不該看到財務資料的編輯者，改用**隔離方案 B**：另建一個只有擁有者能編輯的 Apps Script 專案與部署，專門讀財務摘要；前端呼叫第二個網址，由主儀表板 GAS 簽發短效憑證（HMAC，金鑰存在兩邊的指令碼屬性）證明身分。這樣主儀表板 GAS 的編輯者就碰不到財務資料。方案 B 需要額外的部署權限與金鑰管理，等你決定後再做。

## 2. 資料結構

空白範本：`templates/finance-summary.template.csv`、`templates/decision-log.template.csv`（只有表頭）。

### 財務摘要（分頁「財務摘要」）

| 欄位 | 說明 | 檢查 |
| --- | --- | --- |
| 會計年度 | 例如 2026 | 2000–2100 整數 |
| 截至月份 | 資料截至哪個月；年度預算填 12 | 1–12 整數 |
| 指標代碼 | `revenue`（營收）、`net_income`（稅後淨利） | 只接受這兩個 |
| 指標名稱 | 顯示用 | 文字 |
| 期間 | `annual` 年度、`month` 當月、`ytd` 年初至今累計 | 只接受這三個 |
| 預算金額 | 可空白 | 數字（可含千分位逗號） |
| 實際金額 | 可空白；預算與實際至少要有一個 | 數字 |
| 資料來源 | 例如「2026/06/25 年度預算變更 Excel」「9 月營運報告」 | 必填 |
| 資料版本 | 例如「2026/06/25 預算版本」 | 必填 |
| 更新日期 | YYYY/MM/DD 或 YYYY-MM-DD | 必填、合法日期 |
| 確認人 | 空白 = 未確認 | 文字 |
| 是否已結帳 | 是／否 | 必填 |
| 備註 | | 文字 |

- 表頭與範本不符：整份拒絕，畫面顯示「表頭與範本不符」。
- 個別列不合格：略過並顯示「有 N 列格式不符」，不猜測、不補值。
- 同一指標同一期間有多列時，取截至月份最新、再取更新日期最新的一列。
- 每月人工匯入：確認人把經核對的數字貼進這份試算表即可，不需要改程式。第一階段不提供網頁寫入。

### 週會決策紀錄（分頁「週會決策紀錄」）

討論日期｜議題｜相關專案／業務｜待決策問題｜決策結果｜負責人｜完成期限｜追蹤狀態（待決策、已決策、執行中、已完成、暫緩）。唯讀顯示。

### 存取紀錄（分頁「存取紀錄」）

時間｜姓名｜動作｜結果（ok／denied）。每次讀取都記一筆，包含被拒絕的嘗試。

## 3. 畫面與資料來源對照

| 畫面項目 | 資料來源 | 分類標示 |
| --- | --- | --- |
| 年度營業收入預算、年度稅後淨利目標 | 財務摘要 `annual` 列的預算金額 | 預算版本（顯示資料版本） |
| 實際營收、實際稅後淨利（年初至今） | 財務摘要 `ytd` 列的實際金額；沒有就顯示「尚未連結資料」 | 已確認數據（已結帳且有確認人）／未確認數據 |
| 當月營收、當月稅後淨利 | 財務摘要 `month` 列 | 同上 |
| 淨利目標達成率、剩餘目標差額 | 年初至今實際淨利 ÷（−）年度淨利目標；缺一個就不算 | 管理分析 |
| 進度落後或逾期的專案 | 專案資料（現有 `lagInfo`：逾期或落後 ≥20%） | 自動整理；「高優先級」無資料，標示待人工確認 |
| 7 天內到期的任務 | 專案資料的任務、子項目截止日 | 自動整理 |
| 可能影響請款／收款 | 專案資料的發票期別：已開立、未收款、已過預計收款日；待收款且已過專案結束日 | 自動整理；只含此人權限可見財務欄位的專案 |
| 人力負荷 | 目前進行中的負責＋協作案數 | 待人工確認（無工時與上限資料） |
| 需要主管決策 | 週會決策紀錄中追蹤狀態為「待決策」 | — |
| 業務經營分類 | 專案分類 → 候選經營分類（只計案數） | 建議對應／待確認 |
| 部門 × 業務 | 示意矩陣，格子皆為待定義 | 資料模型示意 |

不加總專案預估收入當作實際收入，不推算專案毛利，也不混用預估銷售額、已認列營收、營業外收入、實際收款、毛利、稅後淨利。

## 6. 本機預覽與測試

```sh
node scripts/preview-synthetic.cjs 8787        # http://127.0.0.1:8787/
NODE_PATH=<全域 node_modules> node --test tests/*.test.cjs
```

- 預覽只綁 127.0.0.1，API 為記憶體替身，全部虛構資料；不連正式 GAS 或試算表。
- 經營檢視白名單（虛構）：`fake-head`、`fake-ops`。其他假帳號（admin、finance、owner、member）都看不到。
- 若要用經確認的真實數字看畫面，把 CSV 放在**儲存庫以外**或 `.private/`（已列入 .gitignore），以 `EXEC_SEED_CSV=<路徑>`、`EXEC_SEED_DECISIONS_CSV=<路徑>` 啟動預覽。不要提交這些檔案。
- `tests/exec-view.test.cjs` 涵蓋：白名單解析與 fail closed、等級不影響權限、列驗證、拒絕讀共用試算表、存取紀錄、四種非白名單角色被拒（含強制打開頁籤與直接呼叫 API）、所有回應／DOM／瀏覽器儲存都沒有財務摘要、達成率與差額計算、缺資料顯示「尚未連結資料」、登出與通行證失效清除、Excel 匯出不含財務摘要。

## 7. 正式上線前要確認的事

1. 兩位指定主管在「權限」分頁的確切名稱（`EXEC_VIEWERS`）。
2. 財務摘要試算表的位置與分享對象；GAS 專案的編輯者名單（決定是否改用隔離方案 B）。
3. 匯入的數字是否已與 9 月自結損益核對；「確認人」由誰填、「是否已結帳」的判定。
4. 候選經營分類的對應（好田、中介、委外）。
5. 部門 × 業務的定義方式。
6. GitHub Pages 的發布來源（目前推測為 `main`，本分支推上去不會發布；請在 Settings → Pages 確認）。
7. 部署順序：先以 GAS 測試部署驗證 `execRead`，再更新正式部署，最後才合併前端。舊版 GAS 沒有 `execRead` 時，前端不顯示頁籤（不影響其他功能）。
